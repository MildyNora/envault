# envault — Design Spec

**Date:** 2026-08-26
**Status:** Approved design, pre-implementation
**Working name:** `envault` (env + vault); rename is cosmetic, nothing depends on it.

## 1. What it is

A local secrets vault for agentic coding: 1Password-style key management, free and
Claude Code-native. The user keeps every API key, token, and password in one
encrypted vault managed through a unified TUI dashboard. Coding agents (Claude Code
first) work only with **aliases** (names) and **ciphers** (asymmetrically encrypted
values). Plaintext materializes exclusively inside the running process that needs
it — never in the agent's context, transcripts, files, or logs.

**Design north star: smoothness.** The workflow must feel exactly like environment
variables. No per-use approval prompts, no ceremony. Protection comes from
construction (no plaintext-emitting commands) and masking, not from friction.

## 2. Problem

- Pasting a key into chat, or letting the agent write it to `.env`, puts plaintext
  into model context, transcripts, and logs — and one prompt injection away from
  exfiltration.
- Managing many keys across many projects is scattered and error-prone.
- Existing tools cover fragments: 1Password `op run` (paid), dotenvx (encrypted
  `.env`), sops+age, Infisical. None have the agent-side half: a plugin that
  teaches the agent an aliases-only workflow plus a unified local dashboard.
  That integration layer is the new thing; the crypto is deliberately not new
  (age / X25519).

## 3. Threat model and explicit boundary

**Protected against (the realistic leaks):**
- Secrets entering model context, chat transcripts, or session logs.
- Prompt-injected or careless read-back: agent running `envault run -- printenv`,
  or code doing `console.log(process.env)` — output masking scrubs the values.
- Secrets at rest in readable files (`.env`, config) — only ciphers exist on disk.
- Accidental commits — everything committable is a name or a cipher.

**Explicitly out of scope (documented, not hand-waved):**
- Code that deliberately exfiltrates a secret over the network at runtime
  (e.g. agent-written code that POSTs its own env to a third party). That is
  egress-firewall territory, not this tool's.
- The clipboard is agent-readable for the ~15s window after a TUI copy.
- Filling *visible* (non-password) browser fields and then screenshotting leaks
  the value into the screenshot; the skill warns the agent against this.

No per-use human approval anywhere: rejected by design in favor of smoothness.

## 4. Architecture

Four pieces; all functionality in one Rust binary.

```
┌────────────┐   ls --json (names only)   ┌──────────────────────────┐
│ Claude Code │ ─────────────────────────► │ envault binary (Rust)    │
│  + plugin   │   run -- <cmd> (masked)    │  CLI · TUI · run · fill  │
└────────────┘                             └────────────┬─────────────┘
      │ reads/writes                                    │ decrypt (age X25519)
      ▼                                                 ▼
 envault.toml (repo,               ~/.envault/ vault (ciphers + metadata)
 names only)                       private key: macOS Keychain only
```

**End-to-end flow:** user: "use my OpenRouter key" → Claude runs
`envault ls --json`, sees alias `openrouter` → writes
`OPENROUTER_API_KEY = "openrouter"` into `envault.toml` and ordinary
`process.env.OPENROUTER_API_KEY` code → anyone (user *or* Claude) runs
`envault run -- npm start` → wrapper resolves manifest → vault → Keychain,
injects plaintext into that child process only, masks it out of all output.
Missing alias → the skill has Claude pause and direct the user to add it in the
dashboard; the value never transits the chat.

## 5. Crypto and vault format

- **Primitive:** `age` (X25519) via the Rust `age` crate. Vetted; no homemade
  crypto. Asymmetric on purpose: the *public* key encrypts, so any party
  (agent, script, import job) can add or carry ciphers; only the *private* key
  decrypts, and only `envault run` / the TUI / `envault fill` ever exercise it.
- **Private key:** generated by `envault init`, stored in the macOS Keychain
  (`keyring` crate; service `envault`, account `age-identity`). Never written
  to disk in plaintext.
- **Public key (recipient):** `~/.envault/recipient.txt`, plaintext.
- **Store:** `~/.envault/vault.json` (override root via `ENVAULT_HOME`).
  One entry per secret:

  ```json
  {
    "alias": "openrouter",          // unique, kebab-case
    "label": "OpenRouter API key",
    "cipher": "<base64-encoded age ciphertext>",
    "url": "https://openrouter.ai", // optional; used by `fill` guard
    "created_at": "...", "updated_at": "...", "notes": ""
  }
  ```

  Metadata is plaintext so listing/browsing never decrypts. The vault file is
  safe for an agent to read (ciphers only), but guardrails block it anyway
  (defense in depth).
- **Global, not per-project:** one vault for the user; projects reference it
  through their manifest.

## 6. CLI surface

By construction, **no subcommand emits plaintext**. The TUI is the only reveal
surface, human-at-terminal only.

| Command | Purpose | Agent-safe? |
|---|---|---|
| `envault` | Open TUI dashboard (requires a TTY; refuses otherwise) | blocked by guardrail |
| `envault init` | First-run wizard: keypair → Keychain, create `~/.envault/` | yes |
| `envault ls --json` | Aliases + labels + dates. Never values. | **yes — the agent's read** |
| `envault add <alias>` | Prompt (hidden input) for a value — or read it from stdin with `--stdin` for piping — encrypt, store | write-only, yes |
| `envault link <ENV_VAR> <alias>` | Add mapping to `envault.toml` | yes |
| `envault import <file>` | Parse dotenv file, encrypt all values, create aliases (kebab of var name), write manifest mappings, print summary + suggest deleting the file (never auto-deletes) | yes (consumes values) |
| `envault run [flags] -- <cmd>` | Inject + mask (§7) | yes — masking protects |
| `envault fill <alias> [--selector S]` | Browser form-fill via CDP (§10) | yes — value bypasses agent |
| `envault guard-check` | Internal: hook helper for the plugin (§8) | yes |
| `envault rotate` | Re-encrypt every secret to a brand-new keypair. Deletes and recreates the Keychain item so its ACL resets — macOS re-asks for authorization, revoking every previously granted "Always Allow". Decrypts all entries up front and stages the new vault before swapping keys, so a failure aborts with nothing changed. | **no — human-only, guard-blocked** |

## 7. `envault run` — injection and masking

1. Find `envault.toml` by walking up from cwd (or `--manifest PATH`).
2. Resolve each mapping — `envault.toml` is flat top-level TOML pairs,
   `ENV_VAR = "alias"`, nothing else; missing aliases → exit 1 listing all
   missing names (no partial injection) unless `--allow-missing`.
3. Decrypt via Keychain identity; spawn `<cmd>` in a PTY (`portable-pty`) with
   parent env + injected vars (injected wins on collision).
4. **Mask everything the child writes** before it reaches the terminal/agent:
   - Replace each injected value with `[envault:<alias>]`.
   - Also match the base64 and URL-encoded forms of each value.
   - Rolling buffer of max-secret-length bytes handles values split across
     output chunks.
   - Values shorter than 6 chars are injected but not masked (collision noise;
     same policy as GitHub Actions).
5. Exit code and signals pass through unchanged. `--env KEY=alias` adds
   one-off mappings.

Latency budget: cold start under ~50 ms so wrapping is imperceptible.

## 8. Claude Code plugin

Standard plugin layout: `.claude-plugin/plugin.json`, `skills/envault/SKILL.md`,
`hooks/hooks.json`.

**The skill teaches the workflow (the product's actual novelty):**
- Never ask the user to paste a secret; never write plaintext secrets to any file.
- Discover what exists via `envault ls --json`; refer to secrets by alias only.
- Wire projects via `envault.toml` + ordinary env-var code; run anything that
  needs secrets through `envault run --`.
- Needed alias missing → tell the user to add it in the dashboard (`envault`),
  wait for their go-ahead. Binary missing → point to install instructions.
- Plaintext `.env` spotted → offer `envault import .env` and deleting the file.
- Form-fill etiquette (§10), including the visible-field screenshot caveat.

**Guardrails (PreToolUse hook → `envault guard-check`, exit 2 blocks):**
- Block agent Read/Bash access to `~/.envault/` (ciphers are safe; blocked anyway).
- Block bare `envault` TUI invocation by the agent.
- Hooks fire only on agent tool calls, so the user's own terminal is untouched.
- Later milestone (not MVP): PostToolUse scrub hook piping tool output through
  `envault scrub` (stdin→stdout replacement done locally in-process) to catch
  secrets leaked by processes *not* run under the wrapper.

Distribution: plugin via a marketplace repo; binary via `brew` / `cargo install`.
The skill checks binary presence and guides installation.

## 9. TUI dashboard

Ratatui. Left pane: secret list (alias, label, key age). Right pane: metadata,
value hidden by default. Keys: `a` add, `e` edit, `d` delete (confirm), `/`
search, `r` reveal (human-only surface), `c` copy with 15 s clipboard
auto-clear, `q` quit. First run with no vault → embedded init wizard.
Refuses to start without a TTY.

## 10. Browser form-fill (`envault fill`)

For "the agent fills the login form but never sees the password":

- Attach over CDP (default `localhost:9222`, `--cdp` to override) to the same
  browser the user's Playwright MCP drives.
- Target the active tab; focus `--selector` (or the currently focused element);
  inject the decrypted value with `Input.insertText` — vault → browser direct.
- **URL guard:** if the secret has a `url` field, refuse to fill when the page
  origin doesn't match (cheap anti-phishing).
- The agent orchestrates (navigate, choose selector, invoke fill) and gets only
  success/failure back.
- Caveats documented: the page's own JS necessarily sees the value (inherent to
  form-filling); screenshots mask password inputs but not visible text fields.

## 11. Error handling

- No vault / no Keychain identity → actionable hint to run `envault init`.
- Keychain access denied → explain the macOS prompt; never fall back to
  plaintext key storage.
- `run` with missing aliases → exit 1, list every missing name.
- TUI without TTY → refuse with explanation (also what the agent hits).
- `fill` with no CDP endpoint → hint how to launch the browser with
  `--remote-debugging-port`.

## 12. Testing

- **Unit:** encrypt/decrypt roundtrip; masking replacer — exact, base64,
  URL-encoded, chunk-boundary splits, sub-6-char skip; manifest parse/resolve;
  dotenv import parsing.
- **Integration:** end-to-end `envault run` against a sandbox vault
  (`ENVAULT_HOME` pointed at a temp dir, file-based test identity instead of
  Keychain): child prints its env → assert output masked, exit codes pass
  through.
- **TUI:** ratatui `TestBackend` snapshot tests for list/add/reveal flows.
- **Plugin:** manual pass for MVP (skill behavior, hook blocking).

## 13. Build order

1. **Vault core** — `init`, `add`, `ls`, `link`, `import`, store, Keychain,
   and `run` with masking. A usable CLI product on its own.
2. **Claude Code plugin** — skill + guardrail hook.
3. **TUI dashboard.**
4. **Browser form-fill.**

## 14. Future (explicitly not MVP)

Linux/Windows keystores (via `keyring` backends), team sharing (age
multi-recipient), PostToolUse scrub hook, Touch ID hardening for TUI reveal,
secret rotation reminders.

## 15. Decisions log

| Decision | Choice | Why |
|---|---|---|
| Runtime delivery | Run-wrapper CLI | User choice; lightweight, language-agnostic |
| Per-use approval | **None** | User choice: smoothness above all; masking + construction protect instead |
| Stack | Rust (ratatui, age, keyring, portable-pty) | User choice |
| Crypto | age X25519, individually sealed secrets | Vetted primitive; asymmetric fits the cipher/alias model |
| Private key | macOS Keychain only | Never plaintext on disk |
| Vault scope | Global (`~/.envault`), per-repo manifest | One dashboard for everything |
| Agent read surface | `envault ls --json` only | Names, never values |
| MVP platform | macOS | User's machine; keyring crate keeps ports open |
| Key rotation | `envault rotate`, human-only; fresh Keychain item resets the ACL | User choice: re-granting "Always Allow" after rotation is the accepted safety compromise |
